# proc-daemon v1.1.3 — Dependency Security Patch

**Date:** 2026-10-08
**Compare:** `v1.1.2...v1.1.3`

## Headline

A dependency-only patch. `cargo audit` reported one vulnerability
and several unsound or yanked crates in the dependency tree. The one
that reaches published builds through a direct dependency is
`memmap2` (RUSTSEC-2026-0186), used by the optional `mmap-config`
feature: its version requirement now excludes the affected releases.
The rest are transitive and are fixed by a `Cargo.lock` refresh.

No source changes. No public API changes. No MSRV change.
Consumers can upgrade with `cargo update -p proc-daemon`.

## What changed

### Fixed — `memmap2` floor raised to `0.9.11`

The requirement was `memmap2 = "0.9"`, which allowed releases
affected by RUSTSEC-2026-0186 (unchecked pointer offset). It is now
`memmap2 = "0.9.11"`, the first fixed release. `memmap2 0.9.11`
declares `rust-version = 1.65`, well under this crate's 1.82.0.

**Migration:** none. Only builds with the `mmap-config` feature
pull in `memmap2`.

### Fixed — lockfile refresh

`Cargo.lock` was refreshed with `cargo update`. A library's lockfile
is not used by downstream crates, so this affects this repository's
CI and development builds. Downstream users get the same fixes by
running `cargo update` in their own projects.

| Crate | Before | After | Advisory | Reached through |
|---|---|---|---|---|
| `crossbeam-epoch` | 0.9.18 | 0.9.21 | RUSTSEC-2026-0204 (vulnerability: invalid pointer dereference in `fmt::Pointer` for `Atomic` / `Shared`) | `crossbeam` |
| `anyhow` | 1.0.102 | 1.0.104 | RUSTSEC-2026-0190 (unsound `Error::downcast_mut()`) | `pprof` (`profiling` feature) |
| `event-listener` | 5.4.1 | 5.4.2 | RUSTSEC-2026-0221 (`!Send` tags could cross threads via `StackSlot`) | `async-std` (optional runtime) |
| `serial_test` (dev) | 3.4.0 | 3.5.0 | drops its `scc` dependency, removing RUSTSEC-2026-0205 | dev-dependency |
| `spin` | 0.10.0 (yanked) | 0.10.1 | yanked release | `pprof` (`profiling` feature) |

## Verification

Local (Windows 11, `x86_64-pc-windows-msvc`):

- `cargo audit`: no vulnerabilities, no warnings beyond the three
  documented allow-list entries in `.cargo/audit.toml`
- `cargo +1.99 clippy --all-targets -- -D warnings`: clean
- `cargo +1.99 clippy --workspace --all-features --all-targets -- -D warnings`: clean
- `cargo fmt --all -- --check`: clean
- `cargo test --workspace` and `cargo test --workspace --all-features`: pass
- The full CI feature matrix (`""`, `tokio`, `async-std`, `metrics`,
  `console`, `json-logs`, `tokio metrics`, `async-std metrics`,
  `tokio console json-logs`, `async-std console json-logs metrics`)
  with `--no-default-features`: pass
- `RUSTDOCFLAGS="-D warnings" cargo doc --workspace --all-features --no-deps`: clean
- MSRV job reproduced on Rust 1.82.0 (fresh lockfile, `indexmap`
  pinned to 2.10.0): `cargo check --lib --no-default-features` and
  `--features "tokio toml"` pass
- `cargo semver-checks` against 1.1.2: no semver update required

## Migration from `1.1.2`

No source-level migration required.
